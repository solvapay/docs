Every host can show text and links returned by an MCP server. They differ in whether the server can draw its own interface inside the chat and where the checkout form appears. When a host cannot show the form inline, SolvaPay returns a link to a hosted page and the host opens it in a built-in browser or hands it to the system browser.

## Capability matrix

| | [Claude](/mcp-hosts/claude) | [Claude Code (terminal)](/mcp-hosts/claude-code#terminal) | [Claude Code (desktop)](/mcp-hosts/claude-code#desktop-app) | [ChatGPT](/mcp-hosts/chatgpt) | [Grok](/mcp-hosts/grok) |
|---|---|---|---|---|---|
| **Text and links** <br /> Plain responses with clickable URLs | Supported | Supported | Supported | Supported | Supported |
| **Render MCP UIs** <br /> Server-defined interface shown inside the chat | Renders inline | Text and links only | Text and links only | Renders inline | Text and links only |
| **Where the payment form appears** <br /> Same SolvaPay checkout, placed where the host allows | Hosted page, in Claude's built-in browser | Hosted page, in the system browser | Hosted page, in the app's built-in browser | Inline in the chat | Hosted page, in the system browser |
| **Account pages** <br /> Plan, usage and billing history, always hosted by SolvaPay | Hosted page, in Claude's built-in browser | Hosted page, in the system browser | Hosted page, in the app's built-in browser | Hosted page, in the system browser | Hosted page, in the system browser |

<Note>
Every host can complete a payment. "Inline in the chat" means the form is drawn inside the conversation by the MCP server. "Hosted page" means the server returns a link to a SolvaPay-hosted page, and the host decides which browser opens it.
</Note>

## How the fallback works

The host decides what to show. Your MCP server sends the same response to every host.

1. Every SolvaPay tool response includes a complete text answer. Any checkout or account action in it is a plain `https://` link.
2. The SolvaPay `account` tool also declares an MCP UI. Hosts that support MCP Apps, such as Claude and ChatGPT, render it inside the chat. Other hosts ignore it and show the text.
3. When a paid tool is blocked, the response text states the limit and includes a link to hosted checkout.
4. If a host renders the MCP UI but does not allow the card form inside it, the UI opens hosted checkout instead.
5. The host opens the link. Claude and Claude Code desktop use their built-in browser. Claude Code in the terminal and Grok hand it to the system browser.
6. After payment, return to the chat. The next call to the paid tool runs.

To build the MCP UI yourself, see the [MCP App integration guide](/sdks/typescript/guides/mcp-app). For the hosted pages themselves, see [Hosted pages](/no-code-mcp/hosted-pages).

## Other MCP hosts

SolvaPay works in any MCP host that shows text and links. Until we have tested a host, assume the hosted-page path: checkout and account pages open from a link in the tool response.

<Warning>
The matrix reflects what we tested on 2026-09-30. Host capabilities change often and without notice, so a cell may be out of date by the time you read it.
</Warning>
